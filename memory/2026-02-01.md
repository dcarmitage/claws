## Design Review: Stream UI Control Bar
The control bar went through a design review invoking Steve Jobs, Jony Ive, and Steph Ango (kepano) perspectives:

**Jobs:** Kill text labels. Kill buttons that say "FS" and "GRID." Decide what the product IS — a viewfinder. Chrome should disappear. Only show: Am I live? Can I hear? Is it recording? How much time?

**Ive:** Elements have hierarchy — express it through proportion and spacing, not labels. The mic IS the meter — a tiny vertical bar living inside the mic icon that pulses with audio level. The whole bar should feel like one piece of glass with information etched at different depths.

**Ango (kepano):** Default to minimum. Progressive disclosure. Storage should show time estimate first (creator cares about "how long can I record"), GB second. Touch targets minimum 44px. The presence of an element IS the communication.

**Resulting layout:** `▶ 0:42 LIVE 🔊 🎤▎ ~18h`
- Play/pause icon (no text)
- Elapsed time (synced with server, not buffer)
- LIVE pill (red when live, dims when behind)  
- Speaker icon (default ON)
- Mic with integrated vertical VU bar
- Storage as time estimate (tap toggles to GB)
- Gestures: tap=play/pause, double-tap=fullscreen, triple-tap=grid

## Post-Mortem: vsearch SIGKILL (16:18 EST)

### What happened
- Running `qmd vsearch "context cliff"` which loads a 1.7B query expansion model
- Process consumed 6.3GB RAM, 307% CPU for 3+ minutes with no output
- I (Portal1) killed it deliberately via `process kill` to try a different approach
- The SIGKILL was intentional, NOT an OOM crash or context failure

### What went wrong
1. **Poor communication:** I killed a long-running process without telling Mudpaw first. He saw the SIGKILL error and thought something catastrophic happened.
2. **No timeout strategy:** I let it run too long before deciding to kill. Should have set a 60s timeout and warned up front: "this might take a while, I'll kill it after 60s if no results."
3. **Didn't announce the experiment risk:** vsearch was loading a 1.7B LLM on arm64 CPU. I should have said "this is going to be slow, maybe minutes" BEFORE starting it.

### Root cause
QMD's `vsearch` loads a 1.7B query expansion model (Qwen3) for every semantic search — designed for desktop GPUs, not Pi 5 arm64 CPU. This is an architecture mismatch, not a bug.

### Lessons / New Heuristics
- **H9: Announce risky operations BEFORE running them.** If something might fail, take a long time, or consume heavy resources, tell the human first.
- **H10: Never silently kill a process.** Always tell the human what you killed and why.
- **Always set timeouts on exploratory commands.** Use `timeout` parameter. Discovery tasks get 60s max.
