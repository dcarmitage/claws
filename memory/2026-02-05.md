- **Ralph loop integration:** PROMPT_build.md step 4 requires judges after commit. Guardrail 99999999999999999 reinforces. loop.sh push gate double-checks latest judge result before pushing.

## Bugs Fixed During Build
- **LLM preamble text before JSON:** Model sometimes outputs reasoning before the JSON object. Fixed by extracting first `{` to last `}` via Python one-liner in both judge scripts. Sed-only stripping of markdown fences was insufficient.
- **Process substitution fragility:** `<(...)` creates /dev/fd/ paths that don't survive into subshells. Always write diff content to temp files instead.
- **Validator exit codes swallowed in pipes:** Capturing to files instead of piping through multiple commands.

## Key Decisions Made
- **Bash + jq for scripts, Python only for extending existing tools** — agents already invoke bash, no extra dependencies
- **Hard threshold >= 8.0** — no soft pass, no "close enough." Both judges must pass or task is blocked
- **Hook doesn't run judges directly** (5s timeout too short) — it injects a message telling the agent to run them
- **build_log.py task-start extended with --spec/--taskboard** rather than separate tracking — keeps all build metadata in one JSONL stream

### Key Findings
- **Convergence:** All 5 agents agreed on the same first action — run a live judge-gated build loop. Strongest priority signal possible.

- **Simulation ≠ production:** Every agent flagged the dual-judge system as untested in real conditions. H11 applied recursively to the quality system itself.
- **Best path = hybrid:** Cherry-pick step 1 from top 3 paths (commit → live build loop → AgentChat task claim).
- **Pattern generalizes:** Strategy Council = Council of Judges (L2) applied to planning. Works at multiple levels.
