## Key Debugging Lessons
- rpicam-vid raw h264 has NO timestamps → use `--libav-format mpegts` or `--libav-format mp4`
- Picamera2 can't just `.start()` after rpicam-vid → must fully close and reinitialize
- Plugin `registerCommand` handler returns `{ text, mediaUrl }` — NOT `{ text, media }`
- `global` keyword required in Python function to modify module-level variables (missed `stream_rec_path`)
- Telegram bot file limit: 50MB (was hitting 16MB limit for some sends)
- ffmpeg `tee` muxer has escaping issues in shell — unix `tee` command simpler and more reliable

## Drive Handshake System
- Each drive identified by UUID (persists across plug/unplug)
- `devices` table in catalog DB tracks all registered drives
- Handshake flow: detect → check UUID → known="welcome back" / unknown="new drive, register?"
- Offline drives: items still searchable, show as offline in catalog
- Transfer: copy + verify + update index + remove source
- Device discovery uses `lsblk -J` (JSON output) for reliable parsing
- camservice + catalog auto-detect USB at `/mnt/media`, fallback to SD card

## Key Debugging Lessons (Watch Page)
- `liveSyncDuration: 999999` at hls.js INIT prevents playback entirely (can't find sync point)
- Same setting at RUNTIME (after stream connects) works fine for disabling auto-sync
- hls.js fatal errors: must destroy + null the instance, otherwise poll sees `hls !== null` and never re-inits
- 404 responses must have CORS headers + plain text (HTML error pages confuse hls.js)
- HUD re-encoding takes ~8-10s for first segment — hls.js needs retry config to be patient
- Old `live = true` boolean leftover after refactoring to `mode` string caused silent global var + broken logic
- Stale HLS segments in stream dir cause ghost playback after stream stops — must clean up on stop
